# fixtures

Fixture files used by no-touch tests.

These files simulate RTK and Headroom outputs so d-token can test parsers, API responses, dashboards, event ledger, and layered savings attribution without touching the user's real local setup.

Rules:

1. Fixtures must not contain real prompts, real code, real command output, real provider keys, or real user paths.
2. Fixture mode must not execute real `rtk` or `headroom` binaries.
3. Fixture mode should be the default mode for GUI demos and parser tests.

## cc-switch fixture

`cc-switch/cc-switch.db` is a deterministic, schema-12 fixture that mirrors the
read-only cc-switch surface consumed by upstream discovery and the
hash-bound auto-follow contract. It is generated by
`support/scripts/generate_cc_switch_fixture_db.py`. The committed database
bytes are pinned by SHA-256, while regeneration compares a canonical
schema/row digest so different SQLite library versions do not create false
cross-platform failures from page-layout differences:

```bash
python3 support/scripts/generate_cc_switch_fixture_db.py --check
```

The fixture embeds a secret-shaped marker and synthetic endpoints only; any
leak of the marker or payload keys fails the candidate contract. The fixture
is never written by d-token and never opened by tests that touch a real
cc-switch database.
