# d-token 应用信息架构与产品契约 (App Architecture & Contracts)

本文档是 `d-token` 桌面端的前端架构全景与不可破坏的业务/安全边界契约，确保重构后能够 100% 严丝合缝地回填映射。

---

## 1. 核心信息架构 (Information Architecture)

应用采用统一的 **AppShell** 框架，包含三大常驻控制面与 8 个固定一级工作台：

```text
┌────────────────────────────────────────────────────────────────────────┐
│ AppShell                                                               │
│ ┌───────────────┬────────────────────────────────────────────────────┐ │
│ │ Shell Sidebar │ Topbar (页面标题 · 连接状态 · 新手引导入口 · 通知)     │ │
│ │               ├────────────────────────────────────────────────────┤ │
│ │ • 总体概览    │ Notification Slot (全局操作/警告提示条)             │ │
│ │ • 安装与连接  ├────────────────────────────────────────────────────┤ │
│ │ • 代码图谱    │ Page Viewport (主工作区滚动容器)                    │ │
│ │ • 分析        │  - 当前选中的页面视图                               │ │
│ │ • 视觉压缩    │                                                    │ │
│ │ • Doctor      │                                                    │ │
│ │ • 变更与回退  ├────────────────────────────────────────────────────┤ │
│ │ • 系统设置    │ StatusBar (端口 18001 · PID · 已连接 Agent · 健康度)│ │
│ └───────────────┴────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────────────────┘
```

## 3. 浮层与辅助视图

1. **首次引导向导 (`modal-onboarding`)**：
   - 欢迎界面 + 3 步步骤条（环境检测 → Agent 发现 → 一键配置完成）；
   - 用户点击一键配置即为对所选 Agent 的明确授权。

2. **系统托盘悬浮窗 (`modal-tray`)**：
   - 360px 宽度紧凑浮窗，供操作系统托盘图标呼出；
   - 包含代理启停开关、今日节省简报、上游健康度、快捷跳转控制台。

## 4. 不可违反的产品与安全边界 (Non-Negotiable Boundaries)

重构 HTML 与 UI 布局时，必须遵守以下契约，否则回填时将被自动化门禁拦截：

1. **单语义 H1 原则**：每个主页面内部必须保留且仅保留一个语义上的 `<h1 class="sr-only">...</h1>`，视觉标题由 Topbar 统一承载；
2. **本地回环 127.0.0.1 强制**：本地代理严格绑定 `127.0.0.1`，绝不可在 UI 或配置中开放公网或任意 IP 绑定选项；
3. **零明文敏感数据**：API Key、Token、用户代码正文、完整 Prompt 绝不上屏，所有流表只显示脱敏后长度与 Token 统计；
4. **事务回退保障**：所有可能修改本地 Agent 配置的操作，必须配对展示备份还原点、受影响文件数与 Diff 差异；
5. **固定一级导航**：一级页面固定为上述 8 个，不得将内部子页面（如 Advanced 或 Logs）提升为顶级导航。
