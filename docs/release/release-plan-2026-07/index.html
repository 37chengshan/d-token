d-token Release Plan · 2026-07

从工程项目到可发布桌面产品

这份计划把 d-token 第一版拆成 5 个阶段：先统一产品信息架构，再打通一键安装、Agent 检测与 cc-switch 上游同步，然后实现智能学习，补齐分析、Doctor、日志和回退，最后完成 UI、稳定性和发布验收。

发布目标 可公开试用的稳定 Beta / 候选发布版，不再按内部 demo 标准验收。
关键边界 d-token 只安装和管理自有本地服务；第三方工具只检测、读取配置和受控写入。
核心突破 cc-switch 上游自动同步 + 智能学习全面扫描 + 文档受控追加/插入。

五个实施阶段

每个阶段都包含研究报告、实施计划和审查结论。建议严格按顺序推进，避免先做高级功能导致基础闭环不稳。

第一版必须守住的边界

这些不是优化项，而是发布门槛。任何实现偏离这些边界，都应该回到 PRD 和计划重新审查。

产品边界

  • 主页面收敛为总体概览、安装与连接、分析、Doctor、变更与回退。
  • 安装与连接页包含一键安装、智能学习、高级安装、日志四个上栏。
  • 第三方工具只检测，不自动安装。
  • 所有真实写入必须有备份、日志和回退。

安全边界

  • cc-switch 默认只读，但必须同步当前上游。
  • 智能学习全面扫描，但默认本地索引、敏感排除和脱敏。
  • 文档写入只能追加或插入 d-token 管理块。
  • 日志和导出不显示完整密钥、token、cookie、prompt、response。

总审查结论

整套计划已经从 PRD 一致性、技术风险、安全风险、遗漏项和发布门槛几个维度做了审查。

建议严格按 Phase 1 → Phase 5 推进

最优先落地三件事：第一，把 UI 导航和第二页四个上栏做出来；第二，把 d-token 服务、Agent 检测、cc-switch 只读读取和上游同步做成真实闭环；第三，把智能学习的全面扫描、受控写入块和回退做成可验证能力。

下一步：把计划交给实现阶段 计划已完成多轮审查并升级为可直接开工的实施规格。建议从 Phase 1 开始，把页面结构、文案、状态和数据来源统一后，再进入真实功能接入。
