# Phase 1：产品信息架构、页面重构与 UI 文案实施规格

## 0. 阶段目标

Phase 1 的目标是把 d-token 从“工程功能集合”重构成用户能理解的桌面产品骨架。完成后，前端实现者可以直接按本文件开始改导航、页面容器、状态文案、空状态和数据来源标识。

本阶段不追求新增后端能力，但必须为后续真实功能留出稳定入口：总体概览、安装与连接、分析、Doctor、变更与回退、设置。

## 1. 多轮审查发现与修正

### 第一轮：PRD 一致性审查

发现：原计划只写了页面方向，但没有明确旧页面到新页面的映射，容易导致实现者继续保留旧导航。

修正：新增旧页面到新页面映射表，要求旧组件只能作为实现来源，不再作为正式信息架构依据。

### 第二轮：UI 状态完整性审查

发现：原计划提到了空状态和错误状态，但没有列出每个主页面必须具备的状态。

修正：新增每页状态矩阵，覆盖 loading、empty、ready、warning、error、success、confirming。

### 第三轮：文案落地审查

发现：原计划有术语替换原则，但按钮、卡片、状态提示还不够可执行。

修正：新增全局术语表、按钮文案表、错误文案模板和危险操作确认模板。

### 第四轮：可实现性审查

发现：如果一次性拆完所有旧页面，风险较高。

修正：采用“导航先收敛，组件渐进迁移”的策略，允许代码文件名暂时保留，但 UI 层必须按新结构组织。

## 2. 页面映射规格

| 新页面 | 旧页面/组件来源 | 页面职责 | 不再承担 |
|---|---|---|---|
| 总体概览 | Overview | 服务状态、Agent 连接摘要、cc-switch 同步摘要、估算节省、最近问题、下一步操作 | 深度配置、开发测试、完整日志 |
| 安装与连接 | Install + Advanced + Compatibility + LogsSecurity 局部 | 一键安装、智能学习、高级安装、安装过程日志 | 全局分析、全局回退 |
| 分析 | Analytics | 价值报告、估算节省、趋势、Agent/上游/错误分布 | 配置修改、诊断修复 |
| Doctor | Doctor | 问题检测、影响解释、自动修复、修复提示词 | benchmark、测试中心 |
| 变更与回退 | Changes | 配置变更、文档写入变更、备份、恢复 | 普通日志浏览 |
| 设置 | Settings | 主题、语言、端口、扫描策略、脱敏策略、数据保留 | 高级路由配置大杂烩 |

正式 UI 导航只显示这些新名称。旧页面名不得继续作为用户可见一级导航。

## 3. 安装与连接页内部信息架构

安装与连接页顶部使用四个上栏标签：

1. 一键安装：服务启动、端口检测、Agent 检测、cc-switch 读取、配置计划、验证。
2. 智能学习：全面扫描、排序、选择、委托、直接写入或提示词模式。
3. 高级安装：自定义 Agent 上游、端口、协议、cc-switch profile、chain bridge。
4. 日志：仅显示安装与连接相关过程日志，不替代全局日志。

每个标签都必须有：

1. 当前状态摘要。
2. 主按钮。
3. 下一步提示。
4. 风险提示。
5. 最近结果。
6. 相关 Doctor/回退入口。

## 5. 关键文案模板

### 服务未启动

标题：d-token 本地服务还没有启动。

说明：启动后，你可以连接本机 AI Agent，并在这里看到连接状态、估算节省和最近问题。

按钮：启动本地服务 / 前往安装与连接 / 打开 Doctor。

### cc-switch 不同步

标题：d-token 当前上游与 cc-switch 选择不一致。

说明：你可能已经在 cc-switch 中切换了配置，但 d-token 仍在使用旧上游。建议同步后再继续使用。

按钮：同步 cc-switch 上游 / 查看详情 / 打开 Doctor。

### 示例数据

标题：这是示例数据。

说明：当前未连接到 d-token 本地服务。启动服务并完成 Agent 连接后，这里会显示真实运行记录。

按钮：启动服务 / 查看连接步骤。

### 危险写入确认

标题：确认应用这次配置变更？

说明：d-token 将修改以下配置，并已准备备份。应用后会立即验证连接；如果结果不符合预期，你可以在“变更与回退”中恢复。

按钮：确认应用 / 取消 / 查看详细 diff。

## 6. 页面状态矩阵

| 页面 | loading | empty | ready | warning | error | success |
|---|---|---|---|---|---|---|
| 总体概览 | 正在读取本地服务状态 | 服务未启动或无请求 | 显示连接与节省摘要 | cc-switch 不同步/最近错误 | 服务不可达 | 服务运行正常 |
| 安装与连接 | 正在检测环境 | 未检测到 Agent/cc-switch | 可配置 | 需要用户确认上游 | 配置失败 | 连接检查通过 |
| 分析 | 正在读取统计 | 暂无请求记录 | 显示趋势和分布 | 数据不完整 | 统计读取失败 | 统计已更新 |
| Doctor | 正在诊断 | 暂无可诊断数据 | 显示检查项 | 有中风险问题 | 有严重问题 | 所有关键项通过 |
| 变更与回退 | 正在读取变更 | 暂无变更 | 显示变更列表 | 有未验证变更 | 回退点不可用 | 回退成功 |
| 设置 | 正在读取设置 | 默认设置 | 可编辑 | 有设置风险 | 保存失败 | 保存成功 |

## 7. 实施计划

### Step 1：导航收敛

修改导航配置，让用户只看到 5 个主页面和底部设置。旧组件先不删除，避免一次性重构过大。

验收：侧边栏不再出现 Install / Advanced / Compatibility / LogsSecurity 等旧工程命名。

### Step 2：第二页工作台壳子

创建安装与连接工作台容器，内部四个标签。先把旧 Install 的服务启动和 Agent 检测放入“一键安装”，旧 Advanced 放入“高级安装”，旧日志片段放入“日志”。智能学习先放结构化空状态和后续入口。

验收：第二页四个标签存在，且每个标签都有清晰说明和下一步。

### Step 3：首页重写

首页从数据大屏改为状态摘要。顶部卡片显示本地服务、Agent、cc-switch、估算节省、最近问题。

验收：首页 10 秒内能让用户知道 d-token 有没有工作。

### Step 4：全局文案替换

按术语表替换主 UI 文案。保留高级详情中的英文术语，但必须有中文解释。

验收：普通用户主路径不需要理解 runtime/payload/adapter。

### Step 5：状态和数据来源补齐

为所有页面统一接入 DataSourceBadge 或等价组件，明确真实数据、示例数据、暂无数据。

验收：任何示例数据都不能被误认为真实运行结果。

## 8. 直接开工任务清单

1. 修改 `src/app/lib/nav.ts` 的用户可见导航。
2. 修改 `src/app/lib/i18n.ts` 中所有主导航和主按钮文案。
3. 修改 `AppShell.tsx` 的页面分组和默认页。
4. 新建或重构安装与连接工作台容器。
5. 为每个页面加统一状态组件：loading、empty、warning、error、success。
6. 给首页加 cc-switch 同步摘要占位。
7. 给所有危险操作增加确认弹窗文案模板。
8. 统一数据来源标识。

## 9. 最终审查结论

Phase 1 已从信息架构、页面状态、文案规范、实施顺序、验收矩阵几个维度补齐。当前没有已知设计缺口，可以直接进入实现。
