# d-token 前端 UI 多维审查与迭代建议

> 审查日期：2026-07-10
> 审查对象：当前 React/Tauri 桌面 App 工作树
> 产品依据：`docs/PRD.md`
> 结论级别：**视觉基础可用，但真实状态、主流程和交互可信度尚不满足稳定 Beta**
> 迭代复核：2026-07-10 后续已落实安装四分栏、智能学习 fail-closed、分析数据守恒和状态栏真实性；原始发现保留用于追溯。

## 0. 迭代复核（2026-07-10，当前 UI）

### 0.1 已完成的重点 UI 迭代

1. **安装页四个上栏目已重做**：现在是占满整横排的四等分任务导航，每栏有 Lucide 图标、主标题、副说明、选中背景与底部强调线，保留 Radix Tabs 键盘/ARIA 语义。
2. **安装主流程已收敛**：删除重复外层标题、重复四张说明卡和重复主 CTA；服务不可用时只保留“安装并启动 d-token”这一主动作。
3. **智能学习不再伪完成**：删除 600ms 假扫描、前端假写入、假备份和假回退；原生扫描未接通时明确禁用，浏览器只显示预览候选并说明不会写入。
4. **分析页数学与语义已修复**：Before 45,000、After 34,500、Saved 10,500、23.3% 使用同一派生模型；策略归因与历史合计守恒；总延迟 2551.2ms 与压缩 450 + 路由 1.2 + 上游 2100 一致；输出缩减标记为示例估算。
5. **分析页信息层级与中文已精修**：拆为“价值概览 / 历史趋势 / 数据范围”，压缩策略、路由表现、成本估算和缓存口径均改为用户可理解文案。
6. **底部状态栏不再把预览当真实**：浏览器预览显示“尚未连接真实路由 / 未监听（预览） / 未运行诊断”，不再显示真实端口和“诊断正常”。
7. **前端回归测试已建立**：目前 5 个测试文件、13 个测试覆盖安装四分栏、唯一主 CTA、智能学习 fail-closed、分析守恒和预览状态真实性。

### 0.2 最新真实视觉证据

- 安装四分栏：`install-nav-refined-1280x720.png`、`install-nav-refined-1180x780.png`、`install-nav-refined-920x640.png`
- 分析页：`analytics-refined-1280x720.png`、`analytics-refined-920x640.png`
- 以上视口均完成 DOM 检查：无水平溢出；920×640 未命名按钮数量为 0；四个安装栏目保持同一横排、等宽且无文字溢出。

### 0.3 仍需继续打磨

1. Overview 仍然以大面积活跃日历为中心，真实连接状态、最近问题和唯一下一步行动应继续上移。
2. Changes / Compatibility / Doctor 尚未完全统一到同一 `RuntimeDataBoundary`；预览/不可用/部分数据状态需要进一步收敛。
3. Settings 的隐私、数据保留、扫描排除、开机启动和更新设置优先级仍低于视觉自定义，需重排。
4. AreaChart chunk 约 386KB、共享 chunk 约 359KB、安装工作台约 134KB，仍有按需加载和图表减重空间。
5. Tauri 原生窗口、焦点环、全键盘旅程、对比度和已安装包级视觉验收仍未全部完成。

所以“用户指定的安装页四栏目”已经按目标落地并有真实视觉证据，但全 App 仍需围绕真实数据边界、核心任务优先级和桌面发布完成度继续迭代，不能因为单页变漂亮就提前结束。

### 0.4 并行 UI/UX 复审（2026-07-10）

独立 UI 复审对两组真实截图与当前源码逐项核对后，确认安装四栏目已经满足“满宽、四等分、同一横排”的核心要求；1280×720 与 920×640 均无横向溢出或相互覆盖。与此同时发现并推动了以下修复：

本轮视觉结论是：安装导航外形已经达标，但“漂亮完美”仍需建立在所有按钮真实可用、危险动作有确认、状态不撒谎、主页面层级符合 PRD 的基础上，不能只靠现有截图宣称完成。

## 1. 执行摘要

当前 App 已形成五个主页面加设置的桌面控制面结构，主导航、基本可访问名称、920×640 最小窗口布局和整体视觉语言已有可用基础。它不是“完全没做”，也不需要推倒重来。

真正阻碍发布的是三类问题：

1. **界面说成功，但真实能力没发生。** 智能学习在 Tauri 环境中只是延时后显示完成；部分页面直接消费硬编码桌面数据。
2. **主流程不够清楚。** 安装页四个栏目还是小字胶囊，页面又有重复标题、重复主按钮和卡片堆叠，用户很难一眼判断下一步。
3. **数据和文案不可信。** 分析页数学不守恒，预览值被标成 `MEASURED`，Doctor 页面与底部状态栏互相冲突，且存在较多中英混排和工程黑话。

本轮 UI 迭代不应只做“换颜色、加圆角”。优先级应是：**真实状态边界 → 安装主流程 → 数据一致性 → 页面信息层级 → 视觉精修 → 自动化与真实桌面验收**。

## 5. 发布阻断项（Blocker / P0）

### FE-001：智能学习制造虚假完成态

- **影响**：用户会相信配置已经扫描、写入并可回退，实际却没有 native IO；这比“按钮不可用”更危险。
- **证据**：`code/apps/desktop/src/app/components/pages/SmartLearning.tsx`；Tauri 真环境扫描仅等待约 600ms，写入通过前端规划和 `setTimeout` 显示成功。
- **整改**：接入真实扫描/计划/备份/应用/验证命令前，正式 Tauri UI 必须显示“尚未接通”或只读预览，绝不能显示“已写入/可回退”。真实流程采用阶段状态机并展示证据。
- **验收**：每个完成态都有 native transaction id、备份位置、写入目标、验证结果和 Ledger 事件；失败与取消不会进入成功状态。

### FE-002：页面数据来源没有统一真实性边界

- **影响**：Runtime 不可用时，Compatibility、Changes 等页面仍可能显示硬编码健康、路由、日志和变更，用户无法区分真实设备与样例。
- **证据**：`src-tauri/src/main.rs::get_desktop_data` 返回大量固定事实；`Changes.tsx`、`Compatibility.tsx` 直接调用，只有 Dashboard 主路径做来源双校验。
- **整改**：建立全 App `RuntimeDataBoundary`：校验 source/schema/freshness；统一 loading、unavailable、partial、stale、preview 和 live 六种状态；所有正式页面只能通过它读取运行事实。
- **验收**：服务停止、数据过期、字段缺失、来源错误时，所有页面一致进入不可用/部分可用状态；不存在硬编码“正常”。

### FE-003：安装页四个上栏目不符合目标交互

- **影响**：小字胶囊页签既不突出安装主流程，也浪费整行空间；在桌面控制面中看起来像次要筛选器，而不是四个关键阶段。
- **整改要求**：改为**占满整横排的四等分任务导航**，不是小胶囊。
- **验收**：1180×780 和 920×640 实际桌面截图均完整显示四栏；每栏宽度稳定、文字不挤压、选中状态清楚、键盘可切换、不会引发布局跳动。

### FE-004：分析数据数学不守恒

- **影响**：Before/After/Saved/Percent、总耗时与阶段耗时、顶部与明细数值互相冲突，直接破坏用户对节省效果的信任。
- **证据**：当前预览出现 Before 45,000、After 34,500、Saved 302,400、58.2%；总耗时 45ms 但阶段耗时 450ms + 2100ms；顶部与明细 removed 数值不一致。
- **整改**：所有派生值来自同一个 typed metrics model 和纯计算函数；保存量=`before-after`；百分比使用同一 denominator；总耗时必须大于等于可串行阶段和，并明确并行阶段。
- **验收**：添加 invariant tests、零值/缺失/部分数据测试；UI 不再保存互相独立的派生数字。

### FE-005：预览态过于像本机真实完成态

- **影响**：Windows 环境中显示 `/usr/local/bin/claude`、cc-switch 已安装、监听端口和诊断正常，会让用户误以为检测已经完成。
- **整改**：浏览器预览只使用“示例设备”或结构空态；所有样例值持续显示明显但克制的“示例”标记；状态栏不得在 preview 中显示真实语气的“诊断正常”。
- **验收**：随机用户仅看首屏即可正确回答“这是示例还是本机状态”；preview 的批准、写入、回退等危险动作默认禁用。

## 6. 安装工作台重点重构规格

这是本轮 UI 的第一优先级视觉与交互改造。

### 6.1 满宽四等分导航

使用一条完整横向导航带，内部为稳定的四列网格：

| 栏目 | 图标建议 | 主标题 | 副说明 | 状态信息 |
|---|---|---|---|---|
| 一键安装 | `Rocket` / `Power` | 一键安装 | 启动服务并连接常用 Agent | 未开始 / 进行中 / 已完成 / 需处理 |
| 智能学习 | `ScanSearch` | 智能学习 | 扫描可复用配置并安全应用 | 未扫描 / 已发现 n 项 / 已应用 |
| 高级安装 | `SlidersHorizontal` | 高级安装 | 自定义 Provider、Route 与实例 | 未配置 / 已配置 n 项 |
| 日志 | `ScrollText` | 日志 | 查看安装、连接和诊断记录 | 新消息 n 条 / 无异常 |

视觉规则：

1. 容器占满主内容宽度，`grid-template-columns: repeat(4, minmax(0, 1fr))`。
2. 每栏有图标、主标题、短副说明和轻量状态；不再使用胶囊按钮。
3. 选中栏使用底部 2–3px 高亮线、轻背景和主文字加深；不使用厚重浮卡或夸张渐变。
4. 栏目之间用细分隔线组织，不把四项做成四张嵌套卡片。
5. 控件高度固定，建议 84–96px；hover/active/loading 不改变尺寸。
6. 920px 宽度时仍保持四列；副说明可缩为单行省略，主标题和图标不可消失。
7. 支持 ArrowLeft/ArrowRight、Home/End 和可见焦点；语义保持 `tablist/tab/tabpanel`。
8. 进行中状态可以使用小型进度线或旋转图标，但不得让栏目跳动。

### 6.2 主内容层级

安装页只保留：

1. 一个页面标题：“安装与连接”。
2. 一句人话说明当前目标。
3. 一条四等分满宽任务导航。
4. 一个主流程区域：状态摘要、唯一主 CTA、问题与下一步。
5. 一个可折叠“高级详情”：路径、端口、runtime、pipeline 等技术信息。

删除外层/子页重复 H1；合并“一键启动并检查”和“启动 d-token”为一个情境化主 CTA：

- 服务未安装：`安装并启动 d-token`
- 已安装未启动：`启动并检查连接`
- 服务正常但 Agent 未连接：`连接常用 Agent`
- 存在问题：`修复并重新检查`
- 全部完成：主 CTA 降级为 `重新检查`

### 6.3 状态机而非卡片墙

主流程统一为：

`待检查 → 检查环境 → 生成计划 → 等待确认 → 应用 → 验证 → 完成/需处理 → 可回退`

每个阶段只显示当前最需要的动作。环境、Agent、能力、服务生命周期不再各自抢一个大卡片；次要信息收进可折叠详情。

## 7. 高优先级问题（P1）

### FE-101：安装页标题、说明和主动作重复

外层和子页面重复“安装与连接”，并同时出现两个相近主按钮。应按上一节收敛为单一标题与单一主 CTA。

### FE-102：中英混排与工程黑话过多

- 当前包括 `Agent connect`、`Detect agents`、`Primary agent`、`Runtime`、`Service lifecycle`、`Route data`、`Token Savings` 等。
- 主界面使用完整中文任务文案；Headroom-derived、CCR metadata、pipeline、route adapter 仅放高级详情，并附一句人话解释。
- 建立文案词典，避免同一概念出现“检查/检测/验证”“服务/runtime”“连接/configure”等多套说法。

### FE-103：概览首屏优先级不符合 PRD

年度热力图占据首屏大面积，但已连接 Agent、最近问题和下一步任务不突出。建议顺序：

1. 当前整体状态与唯一下一步。
2. Agent/Provider/Route 连接健康。
3. 今日节省与请求趋势。
4. 最近问题与变更。
5. 年度活跃度放入二级分析。

### FE-104：Doctor 页面与状态栏冲突

页面显示 runtime/route 警告，状态栏却显示“诊断状态：正常”。两者必须共享同一 selector；未运行时显示“待检查”，部分结果显示“有 n 项需处理”。

### FE-105：变更与回退缺少安全审阅

批准/拒绝前应打开审阅抽屉或对话框，展示人话摘要、精确 diff、目标文件、备份位置、验证方式和恢复方案。Browser preview 中危险按钮禁用，只允许查看示例。

### FE-106：设置页优先级失衡

将设置重排为：

1. 运行与启动：自动启动、服务端口、更新通道。
2. Provider 与 Route。
3. 隐私与数据：保留期、导出、清理、prompt/response 记录边界。
4. 智能学习：扫描范围、排除规则、写入前确认。
5. 通知与诊断。
6. 外观。
7. 高级/开发模式。

主题色、玻璃效果、流速等不应占据设置首屏。

### FE-107：版本来源不统一

fixture 显示 `1.1.8`，前端 package 为 `0.2.0`，Tauri Cargo 为 `0.1.0`。版本必须由构建时单一来源注入，About、Doctor、日志与更新检查使用同一值。

### FE-108：前端没有自动化测试

当前 package 无 test script，也未发现真实 test/spec 文件。至少增加：

- 状态边界测试：live/stale/partial/preview/unavailable。
- 安装状态机测试：失败不会进入成功，取消不丢失原状态。
- 指标守恒测试。
- Doctor 状态聚合测试。
- 危险动作确认测试。
- 核心中文文案/i18n 静态检查。
- 920×640、1180×780 的 Playwright 视觉与无重叠测试。

## 8. 页面级迭代建议

### 8.1 概览

- 用“状态 + 下一步”取代单纯数字墙。
- 每个指标标清 `实时 / 截至 hh:mm / 估算 / 示例`。
- 错误卡优先展示可执行动作，而不是只有计数。
- 年度热力图下沉，不占首屏主视觉。

### 8.2 安装与连接

- 按第 6 节实施满宽四分栏。
- 服务、Agent、Route 组成一条连续步骤，不拆成互不关联的卡片。
- 平台路径由真实检测返回；preview 不展示看似本机的 Unix 路径。
- 高级技术状态默认折叠。

### 8.3 分析

- 拆成“价值概览 / 趋势 / 路由性能 / 高级压缩明细”四层。
- 实测、估算、示例使用不同的标签和说明，不允许 preview 标记 `MEASURED`。
- 图表 tooltip、表格和顶部指标共用同一数据模型。
- 对缺失数据展示空态，不以 0 伪装完整数据。

### 8.4 Doctor

- 顶部只给一个总判断和下一步。
- 检查项按“服务、连接、数据、安全、恢复、平台”分组。
- 每项展示证据、影响、建议；安全修复可一键执行，危险修复进入确认。
- 状态栏与页面使用同一聚合结果。

### 8.5 变更与回退

- 默认显示等待审阅的变更，不直接鼓励批准。
- 完整 diff 可展开；敏感值始终遮蔽。
- 回退点展示创建时间、对应变更、验证状态和可恢复性。
- 部分回退/回退失败必须有明确处理路径。

### 8.6 设置

- 先运行与隐私，后外观。
- 二元设置用开关，互斥模式用分段控件，数量/天数用输入或步进器。
- Dev mode 默认关闭；测试 fixture、benchmark、smoke 不进入正式设置。

## 9. 视觉系统精修建议

1. 页面区块使用全宽 band 或无框布局；卡片只用于重复实体、工具面板和对话框，避免卡片里再放卡片。
2. 卡片圆角控制在 8px 以内，和现有桌面控制面风格保持一致。
3. 标题尺寸服从容器：页面 H1 清楚但克制，面板标题不使用 hero 级字号。
4. 主色只负责选择和关键动作；成功、警告、错误使用独立语义色，避免整屏单一蓝紫色。
5. 所有按钮宽高稳定，loading 不改变布局；图标优先使用现有 Lucide 组件。
6. 固定底部状态栏必须预留内容 padding，确保 920×640 下最后一行不被遮挡。
7. 统一间距、边框、阴影和状态色 token，禁止页面局部自行创造一套近似颜色。
8. 动效只用于状态变化、进度和层级切换，支持 reduced motion，不使用装饰性漂浮元素。

## 10. 性能建议

1. AreaChart chunk 约 386KB，应确认是否可替换为更轻的按需图表，或只在分析页可见时加载。
2. InstallWorkbench chunk 约 136KB，四个栏目继续按面板 lazy-load，首次只加载当前栏目。
3. `useRuntimeDashboard` 的 2.5 秒轮询增加页面不可见暂停、错误指数退避、请求取消和去重。
4. 大列表/日志采用窗口化与增量读取，不把完整 Ledger 一次性塞入 React 状态。
5. 对昂贵派生指标使用 memoized selector，但先保证单一真相模型，不能用缓存掩盖错误。
6. 真实 Tauri 环境记录启动到可操作、页面切换、日志滚动和 24 小时内存曲线。

## 11. 分阶段迭代方案

### Phase UI-0：先恢复诚实状态

1. Smart Learning 未接通部分禁用成功态。
2. 建立 RuntimeDataBoundary。
3. Preview 统一为空态/示例态，禁用危险动作。
4. 修 Doctor 状态冲突和版本来源。

**退出条件**：服务停止或数据异常时，没有任何页面显示伪正常/伪成功。

### Phase UI-1：重构安装主流程并精修视觉

1. 实施满宽四等分导航。
2. 删除重复 H1、说明和 CTA。
3. 主流程改为单一状态机，技术细节折叠。
4. 完整中文文案第一轮。
5. 在 920×640、1180×780、1280×720 做真实截图比较和交互测试。

**退出条件**：用户能在 5 秒内识别当前状态和唯一下一步；四栏占满整行且视觉稳定。

### Phase UI-2：修数据与核心页面层级

1. 建立 metrics 计算模型和守恒测试。
2. 重排概览首屏。
3. 分析页分层，实测/估算/示例严格区分。
4. Doctor 与 Changes 接入真实证据和安全确认。

**退出条件**：所有可见数字可追溯、守恒且有来源；危险动作可预览、可取消、可恢复。

### Phase UI-3：补齐设置、状态和测试

1. 设置页按运行/隐私/学习/外观重排。
2. 覆盖 loading/empty/error/stale/partial/offline/cancelled/rollback failed。
3. 建立 Vitest + React Testing Library + Playwright。
4. 做键盘、焦点、对比度、缩放、长中文和系统字体测试。

**退出条件**：核心状态机和数据守恒有自动回归；最小桌面窗口无重叠、截断和焦点丢失。

### Phase UI-4：真实桌面验收与性能打磨

1. 使用打包后的 Tauri App，而不是只看 Vite 浏览器。
2. OpenCode 作为唯一真实 Agent 流量入口；不得测试 Codex 真实配置。
3. 逐页对照 d-token-owned runtime、Ledger、日志和上游证据。
4. 做 Windows/macOS、明暗主题、缩放、长时间运行和恢复测试。

**退出条件**：显示、动作、日志和真实运行结果一致；性能指标达到发布预算。

## 13. 最终判断

当前 UI 已经有一个可继续精修的控制面骨架，但“漂亮”不能建立在假状态、矛盾数字和重复动作上。先让界面永远说真话，再通过满宽安装任务导航、单一主流程、完整中文、统一状态与克制的视觉系统，把它打磨成可信、稳定、好用的桌面产品。
